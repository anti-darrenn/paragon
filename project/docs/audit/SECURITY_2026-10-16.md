# Security sweep, 2026-10-16

A pre-launch review of the whole project. It covered:

- the Firestore rules, line by line;
- the Hosting headers;
- the client's writes, auth flows and DOM use;
- the admin and notify jobs, and the static-site build;
- the CI workflows;
- the dependencies;
- the whole git history, searched for secrets.

Everything below was checked in the code. Where a claim needed proof, it was
**reproduced**: in headless Chrome against production, against the Firestore and Auth
emulators, or with a read-only audit of production data. That is noted on each row.

The fixes are on branch `fix/security-sweep`. The owner's own steps are in
`LAUNCH_CHECKLIST.md`, under "Security".

## Findings and what was done

| # | Severity | Finding | Done |
| --- | --- | --- | --- |
| 1 | High | **The security headers reached only `/`.** Hosting matches a header `regex` against the *whole* path, so `^/(?:[^_]\|_(?:[^_]\|$)\|$)` matched `/` and one-letter paths only. Every other path went without CSP, `X-Frame-Options`, `nosniff` or a referrer policy, including `/welcome`, where the app opens, and every shared link. Measured with `curl` (`/a` had the headers, `/ab` did not). | Pattern is now `^/(?:[^_].*\|_[^_].*\|_)?$`. `hosting_rewrite_test.dart` matched with `hasMatch`, a partial match, which is how the old pattern passed. It now matches the whole path, as Hosting does, and fails on the old config. |
| 2 | High | **The CSP blocked every lesson video wherever it applied.** `youtube_player_iframe` draws the player in a `srcdoc` iframe. That iframe inherits the page's CSP, and its script loads `www.youtube.com/iframe_api`, which `script-src` did not allow. Reproduced in headless Chrome on production `/`, where most sessions start (the policy stays for the whole single-page session). | `https://www.youtube.com` added to `script-src`. The real player reached `Ready` under the new policy with no violations (local server, headless Chrome). Pinned by a test. |
| 3 | High | **Quota denial of service.** A guest session takes one click and App Check was absent. A script could spend Spark's 20k writes and 50k reads for everyone. | `firebase_app_check` added (`lib/core/config/app_check_config.dart`). It is off until the owner registers a reCAPTCHA Enterprise key, then monitor-only until enforced in the console. The reCAPTCHA hosts are already in the CSP. |
| 4 | High | **Staff role capture.** `apply_roles.js`, `set_role.js`, `set_admin_claim.js` and `create_admin_user.js --upgrade` granted claims by email with no `emailVerified` check. Password sign-up never proves an address, so whoever registered an invited email first got the role. | All four refuse an unverified email (`grantRefusal`, tested). The studio shows a new invite state, "Waiting for them to verify their email", and the job retries it. Audit: the one admin holds a verified email. |
| 5 | Med-High | **Report emails could be silenced for good.** The `flags` create rule did not pin `createdAt`. One report dated 9999 would have moved `_meta/notify.flagsNotifiedThrough` past every real report to come. It also had no field list and no size limits. | The rule now has a closed field set, `createdAt == request.time`, and sizes. `notify_drafts.js` reads only items dated up to now and ignores a cursor set in the future (tested). Audit: no future-dated report and a sane cursor in production. |
| 6 | Medium | **"Delete now" left the data behind.** The client deleted the Auth user first. That signs it out, so every owner-only delete afterwards was refused (`permission-denied`, reproduced on the emulators). The data waited for the nightly orphans job. | New order: check the sign-in is recent (`auth_time`), delete the documents, then delete the Auth user. A guest has no age check. If a guest's session is too old to delete, the app signs them out and the guest job removes the empty account. Tests pin the order. |
| 7 | Medium | **The subject scope trusted the client's label.** Resource rules checked the `subjectId` the client wrote, not the parent topic's. A writer or reviewer limited to one subject could file items under another subject's topic. A writer could also rewrite `createdBy` on a draft and then delete it. For insights, a scoped writer could take over another subject's draft. | The `inItsTopic()` rule reads the topic's `subjectId`. `createdBy` is pinned for writers. Insights keep their subject and need scope on the existing subject too. Audit: the one production item is already consistent. |
| 8 | Medium | **Stored-XSS path through question images.** `build_static_site.js` wrote SVG question images verbatim to `/past-questions/img/*.svg` on the app's origin, and put `width`/`height` into HTML unescaped. An SVG opened directly is a page, and `'unsafe-inline'` would let a script in it run. It was reachable only through an Admin-SDK `imageId`. | `svg_safety.js` (tested) stops the build on an SVG that could run or fetch anything. Sizes are coerced to integers and the asset id is checked. The image path now gets `default-src 'none'; sandbox`. The studio refuses the same SVGs at upload, and the rules type-check `width`/`height`. Audit: 0 SVG assets today. |
| 9 | Medium | **`attempts` had no shape.** Only `userId` was checked: any field, any size, any time, though CLAUDE.md calls `attempts` the future source of truth. | Closed field set, types and sizes, `source` from the seven values, `timestamp == request.time`. Audit: every production attempt has a known `source`. |
| 10 | Medium | **Username squatting.** Guests could reserve names, which are permanent, and nothing was reserved (`admin`, `paragon`, `support`…). | Accounts only, plus a reserved list in the rules, `UsernameRules.isReserved` and the audit script. Linking a guest makes the token's provider `password` or `google.com`, so upgraded guests can still choose a name (probed against production Auth). |
| 11 | Medium | **CI supply chain.** Actions were pinned by tag, including the deploy action that holds the service account. Jobs with write access ran `npm install`, with the token left in `.git/config`. There was no top-level `permissions`. | Every action is pinned to a commit. `permissions: contents: read` everywhere. Checkout uses `persist-credentials: false`. Installs use `npm ci --ignore-scripts`, except the secret-free emulator job. Pushes pass the token for that one step, with git hooks off. |
| 12 | Medium | **Vulnerable dependencies.** scraper had 1 critical and 7 high; rules-test had 1 critical (`tar`). | `npm audit fix` in all four folders, and firebase-tools 15 in rules-test. Now: scraper 8 moderate, rules-test 0 critical (see "Accepted"). Tests pass on every folder, and the emulator suite passes. |
| 13 | Low-Med | **Personal data in public logs and source.** `NOTIFY_TO` is a printed variable. Writer emails appeared in logged subjects. `apply_roles.js` logged emails. `notify_drafts.js` hardcoded two addresses. | The workflow reads `secrets.NOTIFY_TO` first. Logs show counts, uids and masked emails. The hardcoded addresses are gone, and the job skips when `NOTIFY_TO` is unset. A malformed service-account secret no longer echoes into an error. (Git history still holds the old addresses; that cannot be undone.) |
| 14 | Low | **`users` fields not tied to the token.** `email`, `isAnonymous`, `displayName` and `selectedSubjects` were unbounded. Review comments and question `reviewedBy`/`reviewedAt` were unpinned. `lessonAssets.createdAt` was client-chosen. | `email` must be the token's or blank. The other fields are typed and sized, checked only when they change, so old documents are never locked. Comments are sized. Reviewer stamps and asset time are pinned. |
| 15 | Low | **Decompression bombs.** The studio upload decoded before any size check (a small file can declare a huge canvas), and SVG was accepted on its file extension alone. | 20 MB cap before reading. Dimensions are read from the header before decoding (50 MP cap), and only the first frame is decoded. The SVG rules above apply. Tests include a real 20000×20000 header. |
| 16 | Low | **Room route bypass.** `/rooms/:code` passed the address straight to a Firestore path, past the join screen's checks. The YouTube id was not re-checked when rendering. | `roomPathRedirect`: an invalid code goes to `/join`, and a loose one is tidied (tested). `VideoPane` re-parses the id. |
| 17 | Low | **Account enumeration and weak passwords.** The reset message said whether an address had an account. New passwords needed only 6 characters. | The reset message is the same either way. New passwords need 8 (`kMinPasswordLength`); signing in is unchanged. The server-side floor is a console setting. |
| 18 | Low | **Shared computers and release logs.** Sign-out left a WAEC exam in progress, and a guest's device-only notes, in browser storage. Error `debugPrint`s ran in release builds. | Sign-out clears those keys (tested). The studio's draft backups stay, on purpose. The `debugPrint`s are now debug-only. |
| 19 | Low | **Android release build.** It could not reach Firebase (no INTERNET permission in the main manifest), and app data was backed up. | INTERNET permission added, `allowBackup="false"`. Signing and the `com.example` id are owner steps. |

## Checked and sound

- **Secrets.** No secret in any of the 357 commits, in unreachable objects or in a
  tracked file. The Firebase web key is public by design. The key file and `.env`
  were always ignored, and the root `.gitignore` now ignores credentials anywhere
  in the tree.
- **Redirects and links.** `safeNextPath` is closed. No `launchUrl` call takes a
  URL a user or Firestore controls. There is no `innerHTML`, `eval` or platform
  view.
- **Escaping.** Static pages and JSON-LD are escaped (`<` is written `<`), and
  so are the notification emails.
- **Workflows.** No `pull_request_target`, and no `${{ github.event.* }}` in a
  shell.
- **Apple platforms.** No ATS exceptions. HSTS (with preload) is served by Hosting.
- **Rules.** The existing structure held up: owner-only documents, server-time
  stamps, closed field sets on most collections, the room answer rule and the
  custom-claim roles.

## Accepted, and why

- **Client-graded results.** `learn.passed`, `attempts.isCorrect`,
  `challenges.score`, room results and `examResults.correct` are the client's word,
  and `correctIndex` is readable. This is deliberate (CLAUDE.md, "The drill gate"):
  nothing of value hangs on them. Anything competitive must recompute from
  `attempts` on a server first.
- **`'unsafe-inline'` stays in `script-src`.** The YouTube player's `srcdoc` page
  carries inline script that changes with every player (`playerId`), so no hash or
  nonce can cover it. Removing `'unsafe-inline'` would break every video again. The
  places an attacker could inject script are closed separately: images are
  sandboxed and there is no HTML injection in the app.
- **KaTeX (low) and `uuid` under firebase-admin (moderate)** in `tools/admin` and
  `tools/site`.
  - The KaTeX advisory needs an existing prototype pollution plus `trust` turned
    on; `render.js` keeps `trust` off, and the input is our own content.
  - `uuid`'s bug is in v3/v5/v6 with a caller buffer.
  - Both fixes are breaking (KaTeX 0.19 would change every static page's maths;
    firebase-admin 14).
- **rules-test.** Its remaining highs are inside the latest `firebase` and
  `firebase-tools` themselves (npm's "fix" is a downgrade). It is dev-only, in a CI
  job with no secrets.
- **External `https:` lesson figures** can tell a third party a student's IP
  address. Whether to allow-list hosts is a product decision for the owner
  (checklist).
- **Room join throttle.** It is client-side only. Rules cannot throttle, and a room
  code is a 1-in-887-million guess that lasts a day.

## Re-run

- `node tools/admin/security_audit.js` is read-only and exits 1 when anything needs
  attention. Run it before a deploy. Its 2026-10-16 run found nothing: 54 accounts,
  1 role holder (verified), 0 SVG assets, 13 usernames.
- `tools/rules-test` runs `npm test` in CI: 129 checks, every denial above
  included.
- After the rules deploy, `node tools/admin/verify_rules.js` runs against
  production: 159 checks. Its username suite now signs up two throwaway
  `example.com` password accounts.
